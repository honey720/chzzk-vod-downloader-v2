# 릴리즈 규칙 — 버전 · rc · 정식

릴리즈는 **Release 워크플로(`version-bump.yml`) 한 번의 실행으로 시작하고, 소유자가 시작 · 범프 PR 머지 · 초안 공개를 한다.** 에이전트는 요청받은 확인만 한다.

## 버전

- **유저가 체감하는 변경은 마이너, 내부 재설계·버그 수정은 패치.** 타임라인·재생기 보완은 패치로 낸다.
- 버전은 역행하지 않는다.
- 버전 문자열은 Release 워크플로가 정한다 — 브랜치 `dev-X.Y.Z`의 `X.Y.Z`, rc는 `X.Y.Z-rc<N>`(그 버전의 rc 태그 중 가장 큰 N + 1, 없으면 1). **버전 파일을 손으로 바꾸지 않는다.**

## rc

rc는 `dev-*`의 한 시점을 태그로 고정해 **릴리즈 워크플로우로 실제 빌드한 것**이다. `dev-*`의 CI는 테스트만 돌리고 실행 파일을 만들지 않는다 — 실행 파일에서만 드러나는 문제는 rc에서 확인한다.

- **마이너 릴리즈는 rc를 찍는다.**
- **패치는 실행 파일 위험 표면을 건드릴 때 찍는다** — 의존성 · 리소스·파일 경로 · 런타임 조회 · 빌드 설정 · 동봉물. 변경 크기로 위험을 판단하지 않는다.
- rc 태그는 **rc 범프 PR의 머지 커밋**(`dev-*` 커밋)에 붙는다. rc는 `dev-*` 안에서 반복하고, 찍을 때마다 그 시점이 새 기준이 된다.
- ⚠️ **정식 = 마지막 rc + 버전 파일 bump.** 마지막 rc 뒤에 다른 커밋이 들어가면 rc를 다시 찍는다 — 정식 실행이 확인하고 멈춘다.

## 절차

1. **Actions → Release → Run workflow → `dev-*` 선택 → 종류(rc / 정식) → 단계 "1 범프 PR".** 확인을 통과하면 버전 파일 셋만 바꾼 `chore/version-<버전>` → `dev-*` 범프 PR이 생긴다(본문에 확인 결과). 하나라도 거짓이면 PR 없이 멈춘다
2. **범프 PR을 머지한다**(승인). 머지가 다음 단계의 신호다
3. 자동 — rc: 머지 커밋에 rc 태그 → 3-OS 빌드 → AI 노트 → **초안 프리릴리즈**
4. 자동 — 정식: 확인 뒤 `dev-*` → `main` PR(`chore`)을 만들고 **자동 머지(merge commit)를 켠다** → 필수 체크 통과 뒤 머지 → `main` 머지 커밋에 정식 태그 → 정식 빌드 → AI 노트 → **초안 릴리즈**, 같은 버전의 rc 태그 · 릴리즈 정리. `main`이 바뀌는 것은 릴리즈당 이 한 번이다
5. **초안의 노트를 읽고 고친 뒤 Publish한다.** 초안은 쓰기 권한이 있는 사람만 본다. 태그는 초안보다 먼저 공개된다
6. `dev-*`는 머지와 함께 지워진다
7. **외부 이슈를 닫는다.** 소유자가 요청하면 에이전트가 목록을 보고하고, 소유자 확인 뒤 닫는다 — 아래 절

- 3 · 4가 멈추면 워크플로가 **범프 PR에 까닭을 코멘트로 남긴다.** 고친 뒤 같은 `dev-*`에서 단계 **"2 배포 준비만 다시"**로 잇는다 — 1부터 다시 돌리지 않는다(같은 버전의 범프 PR이 이미 있어 1이 멈춘다)
- ⚠️ **4의 PR은 merge commit으로 머지된다. squash를 쓰지 않는다.** squash는 커밋을 새로 만들어 rc 태그가 가리키는 커밋이 `main` 이력에서 끊긴다 — 정식이 rc와 같은 것인지 git으로 확인할 수 없게 된다. 자동 머지는 `--merge`로 켜고, `main` 룰셋도 merge만 허용한다
- ⚠️ 4의 자동 머지를 손으로 끄거나 PR을 직접 머지할 때도 merge commit으로 한다
- 4의 머지 뒤 정식 태그가 안 생기면 **Auto Tag를 손으로 실행한다**(Actions → Auto Tag → Run workflow → `main`). main 끝 커밋의 pyproject 버전으로 태그를 만든다 — Release의 "2만 다시"를 돌리지 않는다(이미 PR이 머지돼 멈춘다)

## 확인 — 워크플로가 한다

| 언제 | 무엇 | 통과 조건 |
|---|---|---|
| 1 (공통) | `chore/version-<버전>` 브랜치 · PR | 없음(PR은 상태 무관) |
| 1 (공통) | 태그 `v<버전>` | 없음 |
| 1 (정식) | `git merge-base --is-ancestor origin/main HEAD` | 참. 거짓이면 동기화(`branch.md`)부터 |
| 1 (정식) | `dev-*` 끝 = 마지막 rc 태그의 커밋 | 같음. rc 태그가 없으면 건너뜀 |
| 4 전 | `origin/main`이 조상 · 마지막 rc 뒤 바뀐 것이 버전 파일 셋(`pyproject.toml` · `uv.lock` · `APP_VERSION`)뿐 · 같은 `dev-*` → `main` PR이 열려 있지 않음 | 모두 참 |

- 결과는 범프 PR · 릴리즈 PR 본문의 "확인 결과"에 남는다
- ⚠️ 4의 머지와 함께 Auto Tag가 rc 태그를 지운다 — rc와의 비교는 그 전에 끝난다(워크플로가 4 전에 한다)

## 외부 이슈 닫기

`dev-*` 머지 때 소유자 외의 사람이 올린 이슈는 닫히지 않고 "v<버전> 릴리즈 때 닫습니다" 코멘트만 받는다(`close-issues-on-dev-merge.yml`). 올린 사람에게는 릴리즈된 시점이 완료다.

1. 목록 — 저장소의 코멘트 전체를 페이지 단위로 읽고 열린 이슈만 남긴다. 이슈 수·코멘트 수 상한이 없다
   ```bash
   gh api --paginate 'repos/{owner}/{repo}/issues/comments?per_page=100' \
     --jq '.[] | select(.body | contains("v<버전> 릴리즈 때 닫습니다")) | .issue_url | split("/") | last' \
     | sort -un | while read -r n; do
       gh issue view "$n" --json number,title,state --jq 'select(.state == "OPEN") | "#\(.number) \(.title)"'
     done
   ```
2. 목록을 소유자에게 보고하고 **확인을 받은 뒤** 닫는다
3. `gh issue close <번호> --reason completed --comment "v<버전>에 포함되어 릴리즈됨 — <릴리즈 URL>"`

## 릴리즈 노트

- 출시되지 않은 코드의 버그 수정은 넣지 않는다. 검증되지 않은 항목은 넣지 않는다.
- AI 노트의 입력은 직전 정식 태그 뒤 머지된 PR 가운데 **PR 라벨**에 `chore` · `documentation` · `skip-release-notes`가 없는 것이다. 범프 PR과 `dev-*` → `main` PR은 워크플로가 `chore` 라벨을 단다.
- 노트는 초안에서 소유자가 고친다. 초안 맨 위의 ⚠️ 경고(API 실패 · PR 번호 불일치)를 읽고 지운 뒤 Publish한다.
