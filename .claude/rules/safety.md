# 안전 규칙 — 개발 대상 밖 · 권한 구역 · 금지

## 개발 대상 밖 접근

**바꾸는 것뿐 아니라 읽는 것도 사전 승인이다.** OS 설정·레지스트리·시스템 상태를 건드려야 하면 먼저 멈추고 묻는다.

- **화면 합성 캡처(`QScreen.grabWindow` 등) 금지.** 위젯 캡처는 **`widget.grab()`만** — 팝업·툴팁도 해당 위젯 객체에 직접 `grab()`한다
- ⚠️ `widget.grab()`은 **윈도우 합성 경계를 재현하지 않는다** — 툴팁·팝업의 `border-radius` 귀퉁이 같은 것은 소유자 실기가 유일한 관문이므로 **"소유자 확인 필요"로 남긴다**
- ⚠️ **`QTest.mouseMove(QWidget)`는 실기에서 진짜 커서를 옮긴다**(`QCursor::setPos`). `QWindow`에 `QTest.mouseMove(window, pos)`로 **합성 이벤트**를 보낸다. 오염을 피한다고 커서를 옮겨 두는 것도 하지 않는다

## ⚠️ pytest 밖에서 앱 코드를 실행할 때

`tests/conftest.py`의 autouse 픽스처는 **pytest 안에서만** `config.CONFIG_DIR`·`CONFIG_FILE`을 임시 폴더로 돌린다.
**프로브 스크립트·계측 코드·렌더 스크립트는 그 보호를 받지 않는다** — `SettingDialog`나 메인 창을 그대로 띄우면 **실제 `config.json`을 읽고 쓴다.**

**pytest 밖에서 앱 위젯을 띄우는 스크립트는 첫 줄에서 config 경로를 임시 폴더로 돌린다.**
읽기만 할 생각이어도 그렇게 한다 — **위젯이 무엇을 저장하는지 미리 다 알 수 없다.**

⚠️ 같은 원리가 **로그·다운로드 폴더·앱 상태 파일 전부**에 적용된다.
**실제 파일에 쓰는 것은 소유자가 앱을 직접 띄웠을 때뿐이어야 한다.**

## 수정 권한 구역

**자유 구역** — 승인된 이슈 범위 안에서 자유롭게 수정:
- `core/` 및 앱 계층 내부 모듈 코드 · `tests/` · `resources/` · `translations/`
- `docs/`의 내용 — **단 `docs/SPEC.md`는 금지 구역이다**

**제안 구역** — 직접 수정 금지. 이슈로 제안하고 소유자가 `approved`를 달아야 착수:
- 디렉토리 구조 변경, 레이어·의존 규칙 변경
- 의존성 추가·제거·교체(`pyproject.toml`)
- 외부 계약 변경(주입 계약, `ProgressEvent`, `DownloadPlan` 등)
- sqlite 스키마 변경

**금지 구역** — 소유자가 바뀔 내용을 보고 동의하기 전에는 수정 금지:
- `CLAUDE.md`, `.claude/rules/`, `CLAUDE.local.md`, `docs/SPEC.md`, `.github/` 전체, 브랜치 보호 설정, 시크릿
- ⚠️ **금지 구역은 소유자의 동의를 받은 내용만 고친다.** 이유는 "되돌리기 어려움"이 아니라 **에이전트가 자기 통제 규칙을 혼자 정하지 않는다**이다 — 되돌리기 쉽다는 사실은 동의 없이 고칠 사유가 아니다.
  - 고칠 일이 생기면 먼저 **바뀌는 줄을 전·후로 강조해 빠짐없이 보이고** 대화에서 동의를 구한다. 동의 전에는 파일을 바꾸지 않는다.
  - 동의하면 **보인 내용 그대로만** 고친다. 고치다가 문구를 더 바꿔야 하면 멈추고 다시 보이고 동의를 받는다.
  - 소유자가 지시문에 볼트 초안(md5)을 지정하면 그 내용을 그대로 옮긴다. 초안에 문제가 보이면 고치지 않고 보고하고 멈춘다.
  - 고친 뒤 커밋된 파일과 보인 내용(또는 초안의 md5)을 대조해 보고한다.
  - 시크릿과 브랜치 보호 설정은 동의가 있어도 에이전트가 다루지 않는다. 소유자가 직접 한다.
  - 실행 환경(Claude Code)이 `.claude/` 아래 파일 수정을 막으면 다른 방법으로 우회하지 않는다. 멈추고 소유자에게 넘긴다.

## 금지 사항

- **`main`·`dev-*` 직접 푸시 금지.** 둘 다 PR로만 들어간다.
- **시크릿(토큰·쿠키·API 키·복호화 키)을 코드·로그·커밋·테스트 픽스처에 포함 금지.**
- **파괴적 git 명령 금지** — `push --force` / `--force-with-lease`, `reset --hard` 후 push, 브랜치 삭제.
  ⚠️ **자기 작업 브랜치라도 예외가 아니다.** 이 금지는 위험도 평가를 에이전트에게 맡기지 않기 위한 것이고,
  **리뷰 중인 PR의 커밋을 날리면 소유자가 보던 diff가 사라진다.** 필요하면 먼저 묻는다.
- ⚠️ **`git checkout -- <파일>`은 되돌리기가 아니라 삭제다.** 그 파일의 **커밋되지 않은 변경 전부**가 사라진다.
  되돌릴 일이 있으면 **먼저 커밋하거나 바이트 사본을 뜬다.**
- ⚠️ **작업 트리(worktree)의 `.git` 파일을 건드리지 않는다.** 그것은 디렉토리가 아니라 본체를 가리키는 한 줄짜리 파일이고,
  훅을 복사한다며 덮어쓰면 **트리가 저장소와 끊긴다.** 훅은 `.git/hooks` 실경로를 조회해서 넣는다.
- 대규모 리팩토링을 임의로 시작하지 않는다. 별도 이슈로 제안 후 승인받는다.
- **머지는 절대 직접 하지 않는다.** 머지는 소유자만 한다.
